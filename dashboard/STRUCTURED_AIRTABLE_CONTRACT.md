# Airtable 结构化交易与风控计划录入契约（2026-10-12）

## 一、目的
自然语言输入可以用来说明意图，但 Airtable 的**数值/日期/状态字段**才是网站判断依据。绝不能从「交易理由」「失效条件」「复盘备注」「策略说明」等自然语言提取价格、股数、交易动作来驱动退出判断。

## 二、两个表：事实与计划分离
1. `交易记录`：每笔实际成交独立新增记录；字段：股票代码、交易标的、操作类型（首仓/加仓/卖出/减仓）、价格（元）、实际成交股数、金额（元）、交易日期、记录日期、交易理由、复盘备注。**仅确认发生的交易才能填实际成交字段**，不能把计划减仓填成已成交。
2. `持仓风控计划`：以六位股票代码匹配，每只股票同一时刻只允许一条「生效」计划；字段：股票代码、股票名称、计划状态（生效/待核验/停用）、生效日期（交易日口径）、预警价格、首道退出价格、首道退出动作（减仓/清仓剩余）、首道减仓股数、最终退出价格、最终退出动作、触发依据（日线收盘/盘中）、策略说明。所有退出价为人民币数字、所有股数为整数；留空表示没有该级规则，不可使用 0 代表未知。

## 三、今后通过自然语言录入
- “我今天在 5.54 元加仓白银有色 2000 股” → 只在「交易记录」新增已确认的成交记录；如果没有改变风险计划，不能自动更改风控价。
- “白银有色收盘跌破 5.48 元减仓 2000 股，跌破 5.35 元清掉剩余” → 只更新「持仓风控计划」中的两个人民币数值、动作、减仓股数、触发依据；不写入实际卖出成交。
- “淮北矿业跌破 15.88 元先关注，日线收盘跌破 15.70 元全部退出” → 15.88 入「预警价格」，15.70 入「首道退出价格」，退出动作选「清仓剩余」，触发依据选「日线收盘」。
- 模糊句子（如“接近前低减仓”）无明确数值、数量、依据时，不猜测：新增/保持「待核验」，请用户补充；不得通过解析备忘录推断。
- 更新既有计划应先校验当前净持仓和同代码的生效计划，避免重复生效；如需留历史版本，旧计划标记停用，然后再激活新计划。不得静默创建多条生效计划。

## 四、判定与界面
- 网站取实时受保护的 Airtable 数据：交易记录汇总净持仓；风控计划单独读取，不公开 GitHub。
- 符合 `计划状态=生效`、有效生效日期、价格>0、首道动作明确、减仓股数不超过净持仓，才参与判断。
- 有效盘中快照：只能描述当轮盘中是否低于设定价格；触发依据=日线收盘时，**不能仅因盘中低于而宣称收盘条件已成立**。
- 预警价只用于提示，不等于退出。
- 多级退出：首道动作可以是「减仓」或「清仓剩余」；最终退出仅支持「清仓剩余」，除非 schema 增加最终减仓股数字段并完成测试。
- 缺少当日有效行情或股票未进入监测池：仍然展示已登记的规则，但提示「待行情」，不猜测是否触发。
- 风控计划不可用、待核验、停用或重复生效：明确显示计划缺失/待核对；**不得回退解析历史自然语言**。

## 六、验收要求
对交易记录、计划匹配、重复生效、超额减仓、多级价格、日线与盘中差异、行情日期及质量运行单元测试。所有数据接口保持 `authorized`、`noStore`。不新增账户密钥，也不在公开仓库记录个人当前持仓。
