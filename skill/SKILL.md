# A股低风险买点榜

## 1. 目标

从 `data/runtime/meta.json` 及其确定性运行时数据中寻找：

> 行业景气没有明显转弱、公司盈利真实且具有持续性、估值具备安全边际、下行风险可控，同时未来 1–2 个季度存在充足且可兑现上行空间的 A 股公司。

本榜单的核心原则是：

> **先控制下行，再比较上行。低风险是准入条件，不是最终排名目标。**

正式目标不是寻找“最稳的股票”，而是在风险可接受的前提下寻找风险收益最不对称、资金效率更高的机会。

本文件是 A 股低风险买点榜的正式选股规则。

---

## 2. 数据与研究边界

正式筛选的机械数据入口只有：

- `data/runtime/meta.json`；
- `meta.industry_state_file` 指向的独立行业状态文件；
- `meta.candidate_files` 列出的全部候选分片；
- `skill/SKILL.md`。

`data/snapshot.json` 继续作为数据生成源与兼容文件保留，但正式运行不直接读取这个大文件。

运行时必须先锁定当前 `main` commit SHA，并在同一 SHA 下读取本 Skill、`meta.json`、独立行业状态文件和全部候选分片，禁止跨 SHA 混读。读取完成后，将全部分片中的 `candidates` 合并为逻辑上的 `snapshot.candidates`；将独立行业状态文件中的 `industries` 作为逻辑上的 `snapshot.industry_state.level3`；其余 snapshot 元数据来自 `meta.snapshot`。后续规则按这个重建后的逻辑 `snapshot` 执行，数据语义不变。

合并后的 `snapshot.candidates` 是唯一机械候选池。正式筛选不得在运行过程中扩展候选池或重新扫描全市场。

行业景气复核、公司确认、估值和上行弹性判断允许查询最新公开资料，用于验证当前候选，但公开资料只承担研究证据作用，不改变候选池边界。

### 运行时读取协议（candidate_shards_v2）

#### 读取不中断硬约束｜最高优先级

本约束优先于本 Skill 中所有研究、输出与错误处理规则。

只要当前正在读取的 GitHub response resource 尚存在任何可继续读取信号，包括但不限于：

- `truncated`；
- `next_start_line`；
- `next_read`；
- `continue from ...`；
- 工具明确提示仍有后续内容；
- 尚未明确到达该 resource 的 EOF。

则当前唯一允许的下一步是：**继续读取同一个 response resource**。

此时严格禁止：

- 输出最终答案；
- 输出 `snapshot_read_incomplete`；
- 判断文件读取失败；
- 跳到下一个 candidate shard；
- 开始正式研究；
- 总结当前读取结果并结束；
- 因上下文长度、工具调用次数或已经读取较多内容而主动停止。

每次读取后必须执行以下内部判断：

`resource_has_more_content == true` → 必须继续读取同一个 resource。

`resource_has_more_content == false` → 才允许检查 JSON 是否完整合法。

只有在**已经明确读到当前 response resource 的最后一行 / EOF**之后，才允许判断：

1. JSON 是否完整合法；
2. `candidate_count` 是否匹配；
3. `trade_date / shard_index` 是否正确；
4. 是否进入下一个 shard；
5. 是否真的需要输出 `snapshot_read_incomplete`。

在准备输出任何最终答复之前，必须执行终止前强制检查：

`pending_resource_continuation == false`

若为 `true`，禁止结束任务，必须继续调用读取工具。

特别说明：

`truncated != failure`

`truncated == continue_reading`

看到 `truncated`、`next_start_line`、`next_read` 或其他 continuation 信号后停止任务，视为执行错误。

1. 锁定仓库 `xwan008/a-market-data` 当前 `main` commit SHA，本轮所有仓库文件都使用该 SHA 读取。
2. 读取 `data/runtime/meta.json`，取得 `candidate_count`、`industry_count`、`industry_state_file`、`shard_count`、`candidate_files` 与 `meta.snapshot`。
3. 完整读取 `industry_state_file` 和全部 `candidate_files`。若 GitHub 返回 `truncated` 但存在 response resource，只表示当前显示被截断，不代表源文件不完整；必须继续读取该 resource，直到获得完整、可解析的 JSON，禁止因单次 `truncated` 提前终止。
4. 校验行业状态：`schema_version = 2`、`trade_date == meta.snapshot.trade_date`、`industry_count == len(industries) == meta.industry_count`；校验每个候选分片：`schema_version = 2`、日期一致、`shard_index` 正确、`candidate_count == len(candidates)`，且候选代码不得重复。
5. 全部文件合并后必须满足：读取候选文件数等于 `shard_count`；`len(candidates) == meta.candidate_count == meta.snapshot.counts.candidates`；每只候选的 `industry_code` 都能在行业状态中找到。
6. 只有某个 response resource 已经读完仍无法获得完整合法 JSON，或最终出现文件缺失、日期不一致、重复候选、行业映射缺失、数量不一致时，才允许输出 `snapshot_read_incomplete` 并终止。在此之前不得因 `truncated` 结束任务，也不得使用 `data/snapshot.json`、search/find、历史榜单、旧候选或计数推断补齐。

## 3. 机械候选池

数据更新链完成确定性粗筛：

- 行业盈利状态为 `improving`，或 `stable + divergent/broad`；
- 非 ST；
- `0 < 股价 <= 120`；
- `PE-TTM <= 30`（有有效数值时）；
- `动态 PE <= 30`（有有效数值时）；
- 净利润为正；
- 财务与价格结构可用；
- 排除收入与利润同时严重坍塌的明显风险样本。

PE 上限按“任一超过即剔除”执行。PE 缺失不自动视为超标，但候选仍必须满足现有估值字段可用性要求。

机械候选池只负责缩小研究范围，不做最终买入判断。

## 4. 数据有效性检查

正式筛选开始前确认：

1. `meta.schema_version = 2`、`meta.runtime_format = candidate_shards_v2` 且 `meta.snapshot.schema_version = 1`；
2. `snapshot.trade_date` 存在且对应最近已完成交易日；

若运行时文件无法完整读取、日期明显过期、市场状态日期错位或全市场覆盖明显异常，则本轮不发布新榜单。

单只股票字段不足，只影响该股票。

## 6. 行业景气复核

`snapshot.industry_state` 代表行业盈利已经兑现的财务结果，是景气判断的基线，但不能单独代表未来景气。

正式筛选需要对候选所属行业补充最新公开信息，判断未来 1–2 个季度的景气延续性。

根据行业特征选择真正有解释力的领先变量，例如：

- 资源 / 化工：商品价格、价差、库存、供需、开工率、产量；
- 制造：订单、排产、产能利用率、销量、招投标、出口；
- 科技：出货、订单、价格、库存、资本开支、渗透率；
- 消费：销量、价格、库存、渠道动销、客流；
- 医药：处方/销售趋势、产品放量、招采、研发兑现；
- 其他行业使用与核心盈利最相关的可验证领先变量。

在产业与盈利领先变量之外增加一层**市场确认**。市场确认只用于提高或降低景气延续性的置信度，不单独决定行业景气，也不得因为短期上涨把基本面转弱行业升级为改善。

市场确认只检查两类信号：

1. **行业广度**：优先观察行业成分股上涨占比，并结合涨幅 `>= 1%` 的有效上涨占比；能够取得连续数据时，再观察近 3–5 个交易日广度是否持续。少数龙头拉动、但多数成分股没有响应，不视为充分确认。
2. **行业活跃度**：优先观察行业当前成交额相对自身近 20 日平均成交额的变化，以及行业内换手率处于约 `1%–5%` 的活跃成分股占比。跨行业比较不得直接使用绝对成交额；相对放量但不过热优于单纯巨量。

使用原则：

- 产业领先变量继续改善，且行业广度与活跃度同步改善：提高“景气延续”的置信度；
- 产业领先变量改善，但市场广度偏窄或活跃度不足：不得仅因此判定“转弱”；若产业证据本身也偏弱，则优先维持“稳定”或标记“不确定”；
- `market_breadth = narrow` 时，市场确认视为 `weak`；其中 `narrow + active` 是比 `narrow + quiet` 更强的风险警告，但不能单独推翻产业基本面；
- 市场广度和活跃度很强，但产业领先变量没有改善或已经转弱：不得反向升级行业景气；
- 单日大涨、单日放量或单个龙头异动不能单独作为景气确认，优先看扩散和持续性。

景气状态归纳为：

- **改善**：领先变量与已兑现盈利方向一致，并继续改善；
- **稳定**：没有明显继续上行，但也没有足以推翻盈利判断的恶化；
- **转弱**：领先变量明显恶化，未来盈利存在下修风险；
- **不确定**：关键证据不足或相互冲突。

正式榜优先保留“改善”，允许证据充分的“稳定”；“转弱”原则上不继续，“不确定”不得进入最终榜单。

行业广度与活跃度只参与内部复核，不因短期市场弱势直接否定基本价值。

## 7. 同行择优

### 目标

从景气复核通过的候选中去掉同类公司里的明显次优者，把研究资源集中到真正值得进一步确认的公司。

同行择优是**横向竞争**，不是单股及格制。公司自身基本面没有恶化，不代表它在本轮仍应保留；只要同一盈利驱动组中出现风险收益比更优的公司，上一轮入选公司就可以被替换。

### 每轮重新构建

每次收盘正式版都必须基于**本次行业景气复核通过后的全部候选**重新构建可比组，并从头完成同行比较与排序。

- 上一正式榜单只允许作为历史参考，不具有自动保留资格；
- 禁止先检查旧榜公司是否仍然成立，再决定是否寻找替代者；
- 禁止因为某家公司此前已经完成过研究，就跳过本轮同组其他候选；
- 同一可比组中的所有当前候选必须在同一套标准下重新比较；
- 即使原入选公司基本面未恶化，只要本轮同行在盈利质量、估值吸引力、上行弹性或当前风险收益比上更优，也应允许替换。

### 分组原则

按“核心盈利驱动 + 真正可比业务”形成可比组，而不是只按宽泛行业分类。同一申万三级行业可以拆成多个不同盈利驱动组；跨行业但盈利驱动高度一致的公司也可以放在同一可比组。

### 比较维度

统一比较五个方面：

1. **盈利兑现**：收入、利润、扣非利润是否真实兑现；
2. **盈利质量**：现金流、利润率、ROE、一次性收益依赖程度；
3. **估值吸引力**：PE-TTM、动态 PE、PB 相对盈利质量是否合理；
4. **业务纯度**：公司利润是否主要来自当前景气改善的核心业务；
5. **独立优势**：成本、规模、产能、资源、渠道、产品、客户或竞争格局优势。

### 市场确认风险修正

`snapshot.industry_state.level3` 中的 `market_confirmation`、`market_breadth`、`market_activity` 和 `market_metrics` 作为同行择优的风险修正项，不采用固定加权总分：

- `strong`：按正常五维比较，质量接近时可更多考虑盈利弹性、业务纯度和景气暴露；
- `neutral`：正常比较；
- `weak`：提高盈利质量、经营现金流、稳定性、规模/成本优势和龙头属性的优先级，降低纯高弹性但现金流较弱或结构脆弱公司的优先级；
- `narrow + active`：视为更强的风险警告；质量接近时优先现金流更强、盈利更稳定、竞争优势更清晰的公司；
- 市场确认只用于同组相对选择，不因短期市场弱势否定基本价值，也不因市场强势升级基本面次优公司。

原则上每个真正可比组保留 **1–3 家**，不强制只留唯一冠军。明显次优者淘汰；无法可靠比较的公司标记为 `research_uncertain`，不进入最终榜单。

### 同行决策审计

每个进入公司确认的可比组，内部必须保留简洁的决策审计：

- 本组胜出公司；
- 主要竞争对手；
- 胜出的主导变量；
- 竞争对手重新胜出的条件。

该审计默认不占用正式榜单篇幅，但用户追问“为什么 A 胜过 B”时必须能够直接解释，不得事后重新编造理由。

## 8. 公司确认

仅对同行择优后的公司做更深确认，重点回答：

> 为什么利润变好了？
>
> 这个驱动还能不能持续？
>
> 当前行业景气和公司经营数据是否共同支持这一判断？

重点核查：

- 主营业务对当前景气改善的真实暴露；
- 营收、核心利润、扣非利润、利润率和现金流是否相互支持；
- 订单、价格、销量、产能利用率、产量或其他适配经营指标；
- 是否存在一次性收益、资产处置、投资收益或会计口径导致的利润失真；
- 当前改善能否延续到未来 1–2 个季度；
- 是否存在足以推翻当前盈利判断的重大反向证据。

无法建立清晰盈利因果链的公司不进入价值判断。

## 9. 价值判断

只对公司确认通过的股票估值。价值判断同时回答两个问题：

> 当前价格是否已经给出足够安全边际？
>
> 在保守假设下，当前价格距离可兑现价值还有多少空间？

主要使用：`pe_ttm`、`pe_dynamic`、`pb`、ROE、当前和未来盈利能力、行业景气状态、盈利稳定性与周期属性、同类公司相对估值。

`PE-TTM <= 30` 和 `动态 PE <= 30` 只是候选池上限，不代表接近 30 就一定便宜。禁止仅因为低 PE/PB 自动判断低估；周期顶部、盈利快速下滑、低质量盈利必须降低估值可信度。

每家公司形成：

- **合理区间**：基于保守至基准盈利假设与合理估值水平得到的价值区间；
- **低风险区间**：在合理区间基础上，根据盈利确定性、周期属性和市场风险加入适当安全边际后得到的低风险参与价格区间；
- **保守上行空间**：优先使用合理区间下沿计算，`conservative_upside = reasonable_range.lower / current_price - 1`。

禁止使用合理区间上沿、乐观盈利假设、行业狂热估值或纯情绪溢价制造虚假的高上行空间。

安全边际不固定使用统一百分比，应随盈利确定性、周期性和市场环境调整。低风险区间不由技术结构反向修改。

若无法形成可信的合理区间、低风险区间或保守上行空间，则该股票不进入正式榜单。

## 10. 低风险准入

低风险不再参与无限排序，而是作为正式机会的**准入门槛**。

股票进入上行弹性比较之前，必须满足：

1. 行业与公司盈利逻辑仍然成立；
2. 当前估值具有明确安全边际；
3. 当前价格进入或接近低风险区间；
4. 存在可以解释的关键支撑、成交密集区或结构失效位置；
5. 当前结构不存在持续恶化，或明确破位后尚未稳定；
6. 如果判断错误，潜在下行风险能够被合理界定。

从 `candidate.price_structure` 读取 `trend_state / break_state / invalidation / nearest_support / nearest_volume_zone` 等信息，形成**执行失效位置**。若存在明确数值失效价，则计算：

`downside_to_invalidation = current_price / invalidation_price - 1`

这里的值表示从当前价下跌至结构失效位置的大致幅度；计算时以正的风险幅度表达。

如果没有可信的数值失效位置，必须保守判断风险，不得因为“60 日位置低”“PE 低”或“看起来接近支撑”自动视为低风险。无法合理界定下行风险的公司不得进入正式排名，可进入等待池。

## 11. 上行弹性判断

只有通过低风险准入的股票，才比较上行弹性。

上行弹性不是历史波动率，也不是单纯“涨得快”。正式判断三个来源：

### 11.1 盈利弹性

判断未来 1–2 个季度，如果当前行业景气延续，公司利润是否仍存在明显增长空间。重点包括：

- 产品价格、销量、订单、产能或利用率是否仍有增长空间；
- 公司利润对行业景气变化是否具有较高敏感度；
- 盈利改善来自主营业务还是一次性因素；
- 利润增长是否能够高于收入增长；
- 当前盈利是否已经接近明显周期高点。

### 11.2 估值修复弹性

判断当前估值距离合理估值还有多少恢复空间。重点包括：

- 当前 PE / PB 与自身合理水平；
- 当前估值与真正可比公司的差异；
- 当前盈利质量是否足以支持估值修复；
- 当前价格距离合理区间下沿和中枢的空间。

低估值只有在盈利逻辑仍然成立时才代表上涨潜力。

### 11.3 上涨兑现条件

理论空间必须有现实兑现路径。优先包括：

- 未来季度业绩继续改善；
- 商品价格、产品价格或行业供需继续改善；
- 新产能、新产品、新订单逐步兑现；
- 成本下降或利润率改善；
- 估值从明显折价状态恢复；
- 其他可验证的经营催化。

没有明确兑现路径的理论上行空间降低优先级。

---

## 12. 非对称机会判断

正式机会必须同时回答：

### Downside

如果判断错误，当前价格到执行失效位置的潜在损失有多大？

### Upside

如果保守判断成立，当前价格到合理价值下沿的潜在收益有多大？

当两者均可合理量化时，内部计算：

`risk_reward = conservative_upside / downside_to_invalidation`

风险收益比只用于机会比较，不把它包装成精确预测，也不允许单独覆盖基本面判断。

### 初始经验门槛

在尚未完成历史结果校准之前，暂时采用：

- 保守上行空间 `< 10%`：原则上不进入正式榜单；
- 保守上行空间 `10%–15%`：仅在盈利确定性很高、下行风险很小且兑现路径清晰时保留；
- 保守上行空间 `>= 15%`：进入优先比较；
- 风险收益比 `< 1.5`：原则上淘汰；
- 风险收益比 `1.5–2.0`：一般机会；
- 风险收益比 `>= 2.0`：具备正式入榜资格；
- 风险收益比 `>= 3.0`：明显非对称机会。

这些阈值属于初始经验参数，未来必须根据真实榜单的最大回撤、5/20/60 日收益、失效率等结果重新校准，不得永久视为固定真理。

---

## 13. 买点确认

买点确认只解决：

> 好公司、好赔率，现在是不是合适的执行位置？

结构只决定执行时机和失效位置，不修改合理区间、低风险区间或理论上行空间。

从 `candidate.price_structure` 重点读取：

- `position_pct`；
- `ma20 / ma60`；
- `high_20d / low_20d`；
- `close_change_5d_pct / close_change_20d_pct`；
- `trend_state / break_state / invalidation`；
- `nearest_support`；
- `nearest_volume_zone`；
- `nearest_resistance`。

优先：60 日区间中低位、当前价接近有效支撑或成交密集区、下跌动能减弱、结构没有继续恶化、上方没有紧邻强阻力。

降低排名或暂不入榜：60 日区间高位、短期快速拉升并远离支撑、明确跌破关键结构且尚未稳定、当前价格明显高于低风险区间。

允许左侧买点，不要求突破确认，但必须明确失效条件。

如果估值上行空间很大，但短期存在紧邻强阻力，则降低当前执行优先级，但不得反向修改公司合理价值。

---

## 14. 市场风险修正

从 `snapshot.market_state` 读取：`trend`、`breadth`、`liquidity`、`risk_level`、`metrics.advance_ratio`、`metrics.above_ma20_ratio`、`metrics.above_ma60_ratio`、`metrics.turnover_ratio_vs_20d`。

市场环境只调整风险容忍度和执行要求，不改变公司基本价值判断：

- `risk_level = high`：要求更大的安全边际、更靠近有效支撑，并提高对非对称赔率的要求；
- `risk_level = medium`：按正常标准执行；
- `risk_level = low`：系统性环境较友好，但仍不得放松个股安全边际要求。

市场强不能把贵股票变便宜，市场弱也不能自动否定真正便宜且赔率良好的公司。

---

## 15. 排名规则

禁止几十项加权总分，也禁止简单使用“安全分 × 弹性分”的机械公式。

正式排名采用**门槛 + 分层比较**：

1. **安全准入**：下行风险不可合理界定或明显不可控的股票直接淘汰；
2. **非对称程度**：在安全股票中优先比较保守上行空间和风险收益比；
3. **盈利确定性**：赔率接近时，优先行业景气与公司盈利驱动更真实、持续、可验证的公司；
4. **上涨质量**：同样的上涨空间，优先 `盈利增长驱动 > 盈利增长 + 估值修复 > 单纯估值修复 > 情绪推动`；
5. **同行相对质量**：赔率接近时，优先具备成本、规模、资源、产能、渠道、产品、客户或竞争格局优势的公司；
6. **执行结构**：最终比较当前价格位置、支撑、成交密集区、上方阻力和结构失效风险；
7. **市场环境**：只做最后风险修正。

因此，**更安全但上行空间明显不足的公司，不应仅凭“更稳”排在上行空间充分且风险仍可控的公司前面。**

## 16. 强行业等待池

对于行业景气明确改善、公司质量通过，但暂时未满足正式非对称机会条件的公司，进入“强行业等待池”。

主要包括：

- **好公司但价格太贵**：当前价格尚未进入低风险区；
- **风险可控但上行不足**：保守上行空间或风险收益比不足；
- **理论空间足够但执行结构未稳定**：需要等待支撑、成交密集区或破位修复确认；
- **行业强但没有个股满足安全 + 弹性双条件**。

等待池必须给出：

- 行业 / 公司；
- 当前未进入正式榜的唯一主因；
- 升级为正式机会所需的关键条件。

等待池不得与正式榜单混淆，也不得为了凑数量把等待池股票强行升级。

---

## 17. 发布格式

正式榜单最多 10 只；不够就少发，可以空榜。

开头用一句话给出当前市场：`trend / breadth / liquidity / risk_level`。

每只正式股票仅输出：

- 排名、代码、名称；
- 当前价；
- 行业景气判断；
- 一句话盈利判断；
- 合理区间；
- 低风险区间；
- **保守上行空间**；
- **核心上涨逻辑**：盈利增长 / 盈利增长 + 估值修复 / 估值修复；
- **下行失效位置或主要风险边界**；
- **风险收益比**（能够可靠计算时）；
- 关键支撑或较优买入位置；
- 主要失效条件。

正式榜后增加简洁的**强行业等待池**，只列真正值得等待的方向，不机械罗列。

结尾输出：

- `snapshot.trade_date`；
- 初始候选数量；
- 行业景气复核后数量；
- 同行择优后数量；
- 公司确认后数量；
- 低风险准入后数量；
- 上行弹性 / 非对称机会判断后数量；
- 最终入榜数量。
