# A股板块趋势榜｜完整趋势状态协议（增量扩展）

> 本文件为“A股板块趋势榜”保留跨轮完整趋势状态管理，并补充仅供观察的资金流向与量价配合证据。既有产业 T0/T1/T2 判定、市场状态判断与迁移条件、全行业扫描、早间增量复核、ETF 时机、新仓优先榜资格/排序/数量、行业路由及写入审计均保持原逻辑。本文件不得作为趋势买点榜或盘中监测的新输入。

## 1. 两份输出与职责边界

- `research/trend_registry.json`：完整趋势状态账本，仅供下一轮**趋势榜**复核；保存新仓优先榜以内、以外的全部已发现且未证实失效的趋势，以及待复核的历史趋势。不能仅根据当期优先榜反推完整趋势池。
- `research/trend_handoff.json`：原格式、原排序、原生成资格，**仅当期新仓优先榜**；供趋势买点榜及其下游盘中快照继续使用。不得混入高潮/衰退但不适合新仓的其他方向，也不得扩展 schema/更改消费者。
- “退出新仓优先榜”与“趋势失效”是不同事件；前者不可自动触发后者。
- 盘中快照由当期 `research/trend_handoff.json` 与 `research/trend_buy_handoff.json` 中冻结的行业和公司名单生成；`research/trend_registry.json` 用于趋势研究记录，不直接扩充盘中监测股票池。

## 2. 读取与事实优先级

每轮趋势榜在原有交易日、日期/模式 Gate 之后，读取 main 的 `research/trend_registry.json`、`research/trend_handoff.json`（需要时）以及原有数据/行业路由文件；记录最新文件 blob SHA。registry 仅提供**历史待复核对象、上期记录与状态转换线索**，不能直接证明当期状态、维持资格或代表今日行情，也不得反向取代当前商品、订单、产业、板块行情与正式全市场扫描。

18:40 完整收盘版仍由**旧版模型驱动的独立全市场产业研究**作为主入口，模型按原有政策/商品/订单/基本面/板块市场结构路径发现与复核主题，并独立核验上期 registry 所有尚未证实失效或待复核的方向。程序化申万行业扫描仅作为**第二条辅助证据通道**，对照原模型初判并查漏补缺，不得代替或决定模型的主题发现、状态、排序或新仓资格。逐一记录保留、状态转换、待复核或已证实失效的证据，不能只审当期 Top 2–3，也不能把 registry 读入视作完成全行业扫描。过去状态只有新证据满足原任务已定义的确认/失效标准才能变化；没有足够新证据时标记“待复核”，原记录及其原始日期保留，不宣称昨天结论今天仍成立。明确失效者保留历史记录而不继续列为有效趋势。

06:40 早间增量版延续原有 previous_trade_date 与隔夜证据规则；只能从同一 previous_trade_date 已完成、已成功提交及 READBACK 的正式 registry 基线做增量复核。隔夜证据不足时状态不迁移，不做全市场收盘版伪重算。若 registry 缺失、日期不匹配、结构无效或为 BOOTSTRAP_PARTIAL，标记 REGISTRY_BASELINE_UNAVAILABLE，不把历史资料当正式基线；在下一次有效 18:40 完整版进行首轮正式全量重建。原有交易日与 handoff Gate 仍必须遵守。

## 3. 正式 registry 数据契约

正式版顶层字段：
- `schema_version=1`, `result_kind=a_share_trend_registry`, `trade_date`, `generated_at`, `timezone=Asia/Shanghai`, `status=COMPLETE`；
- `scan_audit` 至少包含：`full_market_scan_completed`, `previous_registry_trade_date`, `previous_trend_count`, `previous_trend_rechecked_count`, `new_trend_count`, `pending_revalidation_count`, `invalidated_count`, `new_position_count`, `evidence_cutoff_trade_date`。06:40 增量版额外注明模式，不能宣称进行当日全量收盘扫描；
- `trends`：完整趋势/待复核记录集合，稳定主题身份不得因为改名或退出新仓榜重复造身份；每条至少有 `trend_name`, `trend_state`(T0/T1/T2/待核验), `market_state`, `lifecycle_status`(有效/待复核/已失效), `first_seen_trade_date`, `last_verified_trade_date`, `industry_codes`, `industry_names`, `in_new_position_priority`, `supporting_evidence`, `contrary_evidence`, `invalidation_condition`, `change_reason`, `state_history`。证据每项注明来源和日期；历史事件包括原状态、目标状态、日期和原因。待复核历史项必须保留其 last_known_* 原始日期，不得谎称现状；
- `invalidated_history`：保留当轮及历史已验证失效的主题与失效证据/日期，禁止无记录删除；
- `recheck_queue`：针对不能由可靠文件恢复具体历史状态的旧主题，明确标记 provenance/unknown，待下次全市场扫描单独核验，不占用新仓名额。

如果字段名未来要调整，须同步升级 schema 与本协议；不允许静默混用或输出省略号。不得把历史 `高潮/衰退` 自动当成当日结论。完整账本指覆盖本轮能识别的全部现存趋势及未解决历史主题，并不声称从 2026-09-17 之前恢复了不存在的历史资料。

## 4. 初始化与兼容

初始 `trend_registry.json` 如为 `status=BOOTSTRAP_PARTIAL`，只是从已验证文件恢复的**待核验历史线索**，不是已完成的当日完整趋势分析。首次后续有效 18:40 正式运行必须完整扫市场，复核全部现存 bootstrap 条目及 recheck_queue 后才可写 `status=COMPLETE`；旧方向没找到足够当期证据时仍存为“待复核”，不能默默清空，也不得假定有效或失效。

先完成本轮全部研究，构造并校验完整 registry（包括全部旧方向去向），再依据原逻辑生成仅含新仓优先方向的 handoff。正式 handoff **必须继续保持原有 schema 和字段顺序/含义**，不添加任何旧趋势。仅用 handoff 作趋势买点榜及盘中监测输入；不得改变任何下游任务、工作流或文件的读取契约。

## 5. 一致性、提交与失败处理

只有本轮独立研究、数据/覆盖 Gate 与 registry schema/覆盖/状态迁移审计均通过才允许正式落库；先取得 main 的目标文件最新 SHA，JSON.stringify 后再 JSON.parse 验证同一完整 UTF-8 内容。先正常提交 registry，取得新 commit/content SHA，立即重新 fetch + 完整解析并核验日期、主题去重/覆盖、状态转移与新 SHA；只有成功后才能按原任务写 `trend_handoff.json` 并 READBACK。hand-off 的 signals 必须与 registry 同轮 `in_new_position_priority=true` 主题**名称和顺序一致**，但格式必须是原有的简化格式。

任何无法验证的正式全扫、registry 写入失败或 READBACK 不符均报告 REGISTRY_INCOMPLETE/REGISTRY_WRITE_FAILED/REGISTRY_READBACK_FAILED；本轮不得发布一份号称成功的新 handoff，不把未落库内容当已持久化历史。保留原有预写 JSON 验证、错误分类、最小审计和安全检查要求；不要为了完成 registry 绕过拒绝或更换写入通道。

写入结果向用户同时展示“完整趋势池（含高潮/衰退及待核验）”“当期新仓优先榜”以及所有旧趋势的状态变化/退出原因。完整趋势池不设 2–3 名上限；只有新仓优先榜沿用原数量选择逻辑。

## 6. 资金流向与量价配合｜仅作辅助观察，不改原判定

**职责与优先级**：保持原有“产业 T0/T1/T2 × 市场趋势”独立研究、确认/失效标准及全市场扫描顺序完全不变。在按原规则形成板块的市场结构判断后，若有可比且可核验的数据，再补充资金流向与量价配合观察。资金既不构成新的入榜/出榜 Gate，也不单独触发市场状态迁移、T0/T1/T2 调整、趋势失效、ETF 时机、当期新仓资格或排序；不得按净流入绝对金额重新排行。原有相对强度、板块广度、成交、龙头/中票扩散、分歧承接的判定优先。

**观察内容**（同一板块、同一统计口径，优先当日/近5交易日/近20交易日；这些窗口彼此重叠，不可当成三组独立证据）：
- 净流入/净流出方向与金额、可取得时的区间内流入/流出天数；有成交额时观察净流量相对区间成交额的占比，避免不同规模板块只比绝对金额；
- 与各窗口对应的板块价格涨跌、成交量/成交额变化，及原市场链已经核验的相对强度、广度和分歧承接；成交放大本身不能证明净流入；
- 对于“当日资金显著流入，但20日累计净流入较小或为净流出”等情况，检查口径及窗口包含关系，描述为“短期转向待确认”，不得写成“连续20日流入”；同理，单日流出不等同于趋势结束。

**解读与展示**：只使用描述性观察标签“资金与量价相互印证”“资金与价格背离”“短期转向待确认”“暂无明确增量信号”“数据不可用/不可比”。持续净流入与价格、成交和广度同向，可作为已有市场趋势的辅助支持；持续净流出并伴随价格/广度走弱，可作为需要独立复核的反向线索；上涨伴随净流出、净流入伴随滞涨、下跌伴随净流入等背离应如实呈现，不预设为吸筹/出货，也不得单凭资金给出新的状态结论。资金流量是行情数据商依据成交单特征估算的统计指标，不等于可核验的机构仓位变化。

**数据质量与时点**：优先使用明确标注统计方法、板块成分口径、区间和截至交易日的同源数据；不同平台、不同板块分类及可能重复计算的数据不得直接求和或比较。06:40 隔夜版仅能采用符合原 Gate 的上一已完成正式交易日数据，不将盘中/旧数据伪称当日完整数据；18:40 正式版只将已经完整收盘且交易日匹配的数据描述为当日数据。缺少数据、来源日期不一致、统计口径不能对齐时记录不可用/不可比，不臆测、补造或因此阻断原有趋势研究与发布。

**落库与兼容**：不增加 trend_handoff.json 字段、不修改 schema_version、不改变下游输入。若本轮能取得可比资金证据，仅在 trend_registry.json 已有每条趋势的 supporting_evidence / contrary_evidence 中，以注明来源、截至交易日、观察窗口和“仅资金辅助观察”的描述性证据保存；中性、背离及不可用情况可在当轮用户报告中说明，不强制新增 registry 字段或要求为每条趋势取得资金数据。上述资金备注不是新的状态迁移依据；新证据不充分时仍遵守原来的待复核和状态迁移规则。

**本轮输出**：在原有“完整趋势池 → 当期新仓优先榜 → ETF时机/失效条件 → 旧趋势状态变化 → 持久化结果”的报告结构内，为有可靠数据的板块附一行“资金流向/量价配合观察”，标明具体窗口、方向和背离（如有）；无数据时标“未验证”，不因资金缺失删减原榜。


## 7. 程序化板块发现｜旧模型主导、程序辅助互证（不改原确认门槛）

- **唯一决策主体**：18:40 正式版沿用第2节旧版模型驱动的完整市场研究：原产业 T0/T1/T2、独立市场状态、历史主题复核、确认/退化/失效标准、资源商品第一锚、ETF时机以及新仓资格、排序、数量完全不改。模型先按原研究来源独立形成待验证主题及初判；Python不产生另一套正式趋势榜，也没有排序或替换权。
- **独立辅助通道**：如同一完整收盘交易日存在 `data/research/sector_discovery_snapshot.json` 和 `data/research/sector_discovery_audit.json`，读取并核验 schema_version=1、result_kind、trade_date、`no_trade_signal=true`、audit_path、scan_audit及实际行业/概念覆盖。STRONG/EMERGING只是量价发现线索，`model_research_candidates`只是优先**补充核验**名单（通常20条），`candidate_overview`和`deferred_candidates`提供其余行业检查入口，`classification_peer_hints`只是分类邻居提示，不能证明共同产业驱动。Python量化强度分数不是正式主题得分。
- **四类交叉对照**：① 模型与程序都发现：补充量化广度/相对强度等互证，但不能直接升级；② 模型独立发现、程序未触发：按原规则继续研究和保留，检查行业分类、样本/覆盖、时间窗口等程序遗漏，不因未上程序榜而降级；③ 只有程序发现：回到**旧版模型的产业与市场证据规则**独立验证，证据不足列观察/研究线索，不得自动成为趋势或抢占新仓名额；④ 两者冲突：复核市场及商品资料的来源、时间、适用行业和反证，模型仍依原状态/排名规则判断，禁止把单日涨幅与广度当成已确认持续趋势。
- **查漏与产业覆盖**：模型研究旧主题或程序新增线索时，可利用331个申万三级行业的同日摘要补查其他行业及上下游；归并主题必须有真实共同驱动与业务受益证据，不能仅凭行业分类、同日上涨、成分交叠。对每个方向区分已验证的关联行业、仅观察行业及排除行业；行业映射可跨初始Top20，但不应因发现更多代码而自动扩大正式下游股票池。公司主营业务与买点仍由下游单独核验。
- **独立容量边界**：`theme_research_budget`和20个种子行业**仅限制程序辅助线索的优先复核资源**；如多个种子由证据证实为同一主题，可在辅助队列中查漏递补，但不得将旧版模型的全市场研究或历史主题复核置于20项上限之内，更不得强制模型先处理程序种子才能进入主研究。未核验的候选完整记录，不能冒充已深研；20个程序种子也不是20个独立主题或20个交接代码的上限。
- **缺失与失败隔离**：程序文件缺失、过期、状态不一致时标记 `DISCOVERY_UNAVAILABLE`，明确报告辅助量化扫描不可用或仅部分覆盖，不能冒充完成程序扫描；**若原版模型独立完成并可审计原有全市场研究、历史主题复核和其余发布Gate，辅助文件缺失本身不得阻断旧版正式研究及发布**。若原独立研究本身未完成，仍按原规则阻断，不得以程序扫描补齐“已完整研究”的声明。`INDUSTRY_ONLY_PARTIAL`仅表示申万行业扫描有效而无独立概念成分库，不意味着概念全量扫描。
- **审计与交接**：在原 `trend_registry.json` 的 `scan_audit`/支持反证中记录程序日期、覆盖、符合候选、未触发的旧趋势、额外发现的去向、分歧与证据来源；单列“模型独立全市场研究完成”与“程序辅助扫描状态”，`full_market_scan_completed`依原模型研究覆盖证据判断，不得由程序入选数代替。仅依据旧模型最终合格的当期新仓方向，按原 schema 写入 `research/trend_handoff.json`；个股榜和盘中监测仍只读取原正式handoff，不直接读取 discovery。
- **静态主题目录和精简证据快照（辅助层）**：`research/theme_industry_catalog.json`是版本化的、非交易权限的主题—申万三级行业**研究关联目录**；核心行业(core)参与当日客观量价聚合，相关行业(related)仅供研究旁证，不进入核心主题分数，也不自动交接下游。目录当前只覆盖已核验的主题关系，未收录的331行业必须继续由原申万扫描检测并产生`unmapped_industry_alerts`；不能强迫所有行业归属某个静态主题，更不允许程序借静态主题目录替代旧版模型的独立全市场研究。新产业关系需人工/模型核验后版本化维护，不按日涨跌动态改写目录。
- **每日全算、重点提交**：当日已完成交易后，Python对静态目录内**每个主题**按核心三级行业映射，以**去重的个股集合**计算涨幅中位数、近3/5日量价与广度、相对强度、样本覆盖及主题内部行业分歧；一个行业可供多个研究主题使用，同一主题内部股票只计一次，关联(related)不稀释/抬升核心指标。仅将量化强势/启动的少量`research_candidates`、原registry跟踪主题的异常`tracked_theme_alerts`、静态目录外客观行业异动`unmapped_industry_alerts`及覆盖汇总写`data/research/theme_evidence_snapshot.json`；未触发的全部主题统计可以当轮计算后丢弃，不作为正式趋势池，也不要求逐主题全文喂给模型。
- **读取顺序及隔离**：旧版模型先按原规则形成独立趋势初判，之后将同一trade_date且`schema_version=1`、`result_kind=a_share_theme_evidence_snapshot`、`status=COMPLETE`、`no_trade_signal=true`、`auxiliary_only=true`、`decision_authority=legacy_model_driven_trend_research`、`point_in_time_eligible=true`的精简快照作为交叉验证与查漏线索。若文件缺失、过期、版本未知、历史目录时间晚于行情日（`RETROSPECTIVE_MAPPING_SMOKE`），只报告证据不可用，不作为正式研究证据或硬性Gate；原模型原资格/优先次序与下游handoff均不改变。快照的research_candidates**不是**模型新仓优先榜，tracked_theme_alerts**不是**趋势失效指令；模型发现但静态目录未映射的主题仍按原规则独立研究，避免目录天花板。
- **331行业基础分类全部固化（131个申万二级分组）**：`research/theme_industry_catalog.json`中`base_industry_groups`按申万2021行业编码前四位确定二级类别，全部331个在库申万三级行业**恰好归入一个**基础分组；每组保存正式行业代码/名称与层级，发生分类或公司目录变更时须先版本化更新目录并通过覆盖/名称/无重复校验。二级分组只表示申万行业统计层级，**不是**另一套独立产业投资主题，更不代表该组具备T0/T1/T2或可交易趋势。`themes`继续单独保存17个经历史研究支持或用于研究种子的跨行业主题；将来可以因经过核验的产业关系新增/修订主题，不必等到行情上涨，但不能靠行情自动固化虚构主题。
- **每日全算、精选输出的完整覆盖语义**：Python每天分别计算17个研究主题与131个基础行业组，验证331个申万三级行业基础组覆盖100%且每个行业仅在基础组内出现一次；跨研究主题重叠是有意设计的，不能把不同组的公司数或强度相加当作全市场总量。最终精简快照的`research_candidates`只按补充研究价值择优列出两类证据，标明`evidence_group_type=RESEARCH_THEME`或`SW_L2_TAXONOMY`，不要把基础行业组的STRONG/EMERGING直接解释成“投资主题趋势形成”。`unmapped_industry_alerts`在完整基础分类上线后改指“**尚未关联到独立研究主题**的量化强势行业”，不是没有基础申万分组。保持原模型独立研究顺序、完整趋势池与最终新仓资格排序不变。
- **历史时点、非预测与安全**：程序阈值只用于发现与查漏，未验证预测力。使用同一已收盘日期及有来源的历史证据，禁止未来数据、事后新闻回填及调整原趋势确认规则以适配某一案例；不自动下单。模型可以因**按旧规则独立核验的新证据**改变排名，但不得因Python分数或程序漏报机械改变状态、排序、准入。


## 8. 严格历史回放与多日误报代理

- 回放以历史实际 Git 提交 SHA 封存的当日 `data/latest.json`、`data/research/company_industry_index.json`、`data/research/full_market_price_structure.json` 为独立输入；三者日期必须匹配，任一缺失应阻断该日期验证，不以更新日期的价格结构或今日映射代替。
- 所有发现结论必须先在各交易日独立冻结；未来交易日的快照只能用于**事后评价**。不得利用10月9日新闻、价格或资金情况调整10月8日的入选结论；不得用10月8日过后的概念成分补充当日信号。
- **误报代理不是投资亏损率，也不是“情绪炒作率”**。可比较下一/下两个完整交易日固定初始行业成分的中位价格表现是否同时为负且相对全市场为负；同时报告可评估样本数、右删失样本和覆盖失败样本，不以信息不足为成功或失败。
- 回放结论应明确区分程序识别（合格、待研究、样本不足）与模型最终市场状态判断（T0/T1/T2及趋势晋级）；程序成功发现并不能证明已经完成深度产业验证。
- 多交易日回测是测试发现率、研究成本及后续延续性的基线，阈值调参需要独立样本，不得仅以2026-10-08/09粮食案例过拟合。


## 9. 补充研究与行业代码交接｜不替代原模型研究

- **程序输出定位**：`model_research_candidates`（初始Top20）只是辅助核验入口；`candidate_overview`保留全部量化合格行业，`deferred_candidates`是辅助资源限制导致的延后队列，不等于市场趋势未成立；`all_industry_metrics`指向全申万行业客观摘要。研究程序不得直接决定正式主题池范围、T0/T1/T2、市场状态、ETF、交易建议、新仓排序或下游industry_codes。
- **原版研究不被容量限制**：旧版模型先完成原有全部市场/产业研究、历史registry主题逐项复核，再把程序发现与既有研究结论逐个交叉核对。约20项的容量配置仅限制**程序候选补充研究工作量**，不是全市场研究数、旧主题研究数、正式新仓榜容量，不能把程序排序的前20条变成正式主题初选Gate。若程序内真实同主题证据使研究工作重合，释放的辅助资源可审视下一批线索；不能为了凑数强制制造新主题或迁移旧版状态。
- **共同主题和行业扩展**：产业归并以及申万三级行业映射都必须以同日真实共同驱动/上下游盈利传导为依据，辅以行业广度、相对强度、分歧承接、反证与样本规模。一个模型确认的主题可以有多个经验证的代码（包括程序未入前20或程序没有触发者）；程序分类相近、同日上涨、单股关联不是充分条件。仅观察/产业受益尚不明确的行业只能在registry研究证据中记录，不进入正式handoff。
- **纠偏实例的通用原则**：程序检测到新强势行业，不能因为该行业单日涨幅大就直接替换既有趋势；若原有行业未被程序触发，同样不能据此将旧趋势降级。商品反证须核对具体品种与行业（如焦煤与动力煤），不能未经验证否定整个主题。所有增删、状态迁移和优先级调整必须列出**旧版模型的原有标准与具体证据**，不能创造额外的挑战者门槛、固定连续天数、稳定性加分或新独立排名算法。
- **追溯**：registry的现有 `scan_audit`记录本轮模型先行研究与辅助程序交叉对照结果：共同发现、模型独有、程序独有、证据冲突、证据日期、处理去向、遗漏/容量延后；已有主题只因新证据按旧判定标准改变状态；完整审计保留未验证程序候选。程序缺失时清楚列明辅助缺口，而不是将模型自身全市场研究冒充为程序完成。
- **正式身份预检与兼容**：`research/trend_handoff.json`继续采用原 `schema_version`、`signals`字段及原资格/排序规则。若已按旧规则独立决定某主题的真实业务关联及应当交接的申万三级行业，校验 `industry_codes`/`industry_names`等长、同一 `trade_date`的 `data/low_risk/index.json`、有效非空公司池、已声明manifest及registry一致性；可运行 `scripts/validate_theme_handoff_routes.py` 做身份预检。该校验只证明代码身份可路由，不代表该行业全体公司实际受益，不替代下游完整manifest/parts、硬过滤、业务证据、买点和风险审查。
- **下游完全不变**：不改变趋势买点榜的每三级行业动态Top5、每主题最终Top5、READY/WAIT、个股仓位/退出及盘中监测。任何正式趋势与买点的发布必须依原有研究覆盖、来源、日期、完整性、GitHub提交和READBACK门槛；程序发现永远不能单独造成正式交接。
## 10. 前瞻性发现来源归因｜模型 vs Python（仅研究审计，不改交易策略）

**目的**：从本规则生效后的完整收盘研究开始，记录“最早在本轮独立发现了什么、程序额外提示了什么、模型最终是否独立核实”，为以后比较不同发现渠道的有效性和误报率提供可复核样本。此字段仅是**发现渠道标签**，不是趋势质量、投资建议或产生超额收益的证明。不能用最终榜单倒推是谁首先发现，也不能把程序的量价信号说成完成产业研究。

**强制顺序（18:40 完整版）**：
1. 在读取**本轮** Python 辅助快照（sector discovery、theme evidence 的候选及异常清单）之前，按第2/7/9节先完成模型自身全市场产业研究与上期 registry 全量复核，形成**第一轮独立发现清单**；记录每个方向的规范名称、已核验的申万三级行业代码、是新发现还是旧趋势复核、主要依据/截至日期。将该名单冻结在本轮研究记录中，后续只能追加解释，不得在看见 Python 后逆向改写或补报为“模型先发现”。不能预先从当天 Python 榜单或其衍生转述中获得候选线索。
2. 再读取同一收盘交易日且校验合格的 Python 快照（含 research_candidates、unmapped_industry_alerts、sector_discovery 的模型复核队列）；按真实行业关联和产业主题身份去重，记录文件 blob SHA 与交易日。申万二级统计分组和跨行业主题可能重叠，不得把同一机会虚增为数条。
3. 以**冻结的首轮模型名单**和程序的**正向发现候选**求并集逐项标记来源。只有记录明确表明模型初判中已经有该方向，才可计模型发现。Python 的 tracked_theme_alerts 是对旧趋势的风险/异动复核，不等同于“新发现”；程序未输出候选不能证明模型错过机会。对只由程序提出者，必须按旧版产业/市场准则做独立验证。标注最终采用/待复核/排除/合并，保留未上正式榜的候选，禁止只统计胜出者。
4. 如果第一轮名单没有在接触程序之前明确冻结、Python 缺失/过期或行业身份匹配不清，逐项标记 `UNVERIFIED`，不得事后猜成模型或程序；不要为了凑完整来源标签阻断旧版正式发布。06:40 早间只复核上次收盘记录，不构造新的发现来源样本。若只在同一轮最终JSON中记录冻结清单，来源标签只作为本轮**声明式研究审计**，不能称为已独立证明“先于程序阅读”。

**来源标签**（针对本轮*正向发现*、非历史成立趋势）：
- `BOTH`：模型首轮独立候选和同日 Python 正向发现候选都包含该规范产业方向。
- `MODEL_ONLY`：模型首轮已有，Python 当日有效覆盖下未触发正向候选。
- `PYTHON_ONLY`：模型首轮没有，首次通过同日 Python 正向候选进入本轮研究；即便最终经模型核查后被排除，也保持此来源标签。
- `UNVERIFIED`：历史首次发现来源无法证明，或上述先后、有效性、映射无法确认；不能反向补造来源。
来源与最终判断分别记录，不允许把 `PYTHON_ONLY` 等同于正式趋势确认，也不得把 `BOTH` 当成两条独立产业证据。

**落库位置、最小兼容结构**：仅在 `research/trend_registry.json.scan_audit.discovery_attribution` 中新增本轮审计对象（`schema_version`仍为1，因为 `scan_audit` 为可扩展审计）；至少包含：
- `trade_date`、`method="MODEL_FIRST_THEN_PYTHON"`、`model_first_pass_frozen`（仅在真实先行冻结时为true）、`model_first_pass`（主题、三级行业代码、证据日期与新旧复核标记的清单），`python_snapshot_trade_date`、`python_snapshot_blob_shas`（文件路径和真实 SHA，缺失如实记录）。
- `candidates`：本轮模型独立候选与 Python 正向候选的**去重并集**，每条包含 `direction`、`industry_codes`、`origin`、`model_first_pass_hit`、`python_positive_hit`、`python_source_types`（例如 `research_candidates`/`unmapped_industry_alerts`/`sector_discovery`）、`disposition`（`INCLUDED`/`PENDING`/`REJECTED`/`MERGED`）、`canonical_trend_name`（可为空）、`reason`。程序发现但最终未入榜、来源不明确者仍必须保留记录；已有旧主题的单纯风险预警另记 `recheck_alerts`，不得误计为新发现。
- `attribution_status`：`DECLARED_IN_RUN`（同轮记录了冻结清单、仅为声明式来源归因）、`VERIFIED_PRECOMMIT`（确实在查看程序前独立提交首轮清单并完成READBACK，且记录对应commit/blob SHA）或 `UNVERIFIED`（清单缺失、来源无法区分等）。不能将 `DECLARED_IN_RUN` 的来源标签误报为独立审计证实；没有预先持久化的前提下先进行低成本观察，不强制新增文件、Git提交或原正式发布Gate。
- 凡有真实可验证的首次识别来源，后续历史记录不得将其改成另一来源；本规则上线前的首次发现一律 `UNVERIFIED`，不得对10月12日及之前的主题做事后标签回填。

**以后实战验证**：将每个方向的首次发现交易日、当日**冻结的**申万行业/样本范围及来源标签作为起点；用首次发现后5/10/20个完整交易日的行业收益、相对全市场超额、趋势延续/失效及误报代理观察三种来源，不使用未来成分股或未来数据回写旧样本。必须同时比较未纳入正式榜的程序/模型候选，说明同期市场环境、样本量、风险暴露与右删失；分别统计“发现后市场表现”和“最终正式入榜后表现”，不得只看盈利个案或把相关性当因果。样本不足时只描述结果、不宣布某渠道胜出。

**下游完全隔离**：`research/trend_handoff.json`、趋势买点榜、盘中监测、Python 输入/指标、正式趋势判定门槛、排名及交易规则均不变；本功能仅新增审计元数据和当轮报告中一列来源标签。
