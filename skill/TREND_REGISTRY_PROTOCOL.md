# A股板块趋势榜｜唯一正式研究与发布协议

> **唯一业务规则入口**：「A股板块趋势榜」每次执行（06:30和18:30）都必须先完整读取并遵循本文件。本文件规定通用研究方法、状态判断、有效趋势复核、退出判断及发布纪律，不包含上一轮热门主题或推荐名单。**06:30读取标准后，只对上一有效收盘的确认/候选趋势做增量复核；18:30读取标准后，必须先独立完成并冻结全市场发现，再读取上一轮有效趋势记录。**
>
> **每天的正式研究只有三步**：模型独立发现 → 仅候选/确认连续复核 → 合并判断、校验发布。Python只负责客观行情计算和必要技术校验，不作为第二个趋势发现者。保留现行T等级、市场状态、买点榜资格/顺序/数量及handoff下游契约；仅确认和候选方向进入持续跟踪。

## 0. 每次执行前必读｜通用产业与市场研究标准

**产业链和A股市场链分开判断。** 研究对象是未来可能持续的产业景气及其在A股的市场体现；发现候选不等于趋势已确认，确认产业趋势也不等于立即值得买入。

1. **产业链的领先变量与未来1–2季度驱动**：判断未来1–2个季度盈利改善是否存在可核验路径；分开核实政策落地、产品价格/价差、库存与供需、订单与交付、产能利用、成本/毛利传导和经营利润。区分已发生事实、前瞻条件、未证实假设。单一政策口号、热点新闻、市场涨幅不足以证明盈利已改善。
2. **产业T阶段（证据成熟度而非股价级别）**：T0拐点观察——产业领先变量发生有来源的变化，但需求/利润传导尚不完整；T1准景气确认——多类有效证据支持未来1–2季度产业或盈利改善的驱动，关键传导与潜在反证已审查，尚未充分兑现；T2正式景气——有真实订单、供需、价格/价差、盈利或利润率等互相支持的兑现证据，产业链条相对充分。资料不足则待核验，不强凑T1/T2；正式迁移仍服从现行程序Gate。
3. **独立A股市场阶段**：只按可比的相对强度、上涨广度、成交变化、价格结构、龙头与中票扩散和分歧承接判断。新异动为早期异动；观察为有跟踪价值但尚未确认；候选趋势为量价与扩散出现初步共振但持续性待验；趋势确认为市场结构、广度、相对强度与分歧承接获得相互支持的可靠确认；根据截至本轮有效收盘已掌握的真实证据判断，不设固定上涨天数、累计窗口或单日广度比例作为确认硬门槛；高潮/衰退为过热或扩散明显衰减；失效为按真实结构反证确认市场趋势结束。**状态不是必须逐级经过的机械序列**，要依客观证据判断。
4. **正向证据、反向证据和失效条件**：每个进入正式有效趋势池的主题都要有具体正向证据，主动核查至少一项潜在推翻路径，写明指标、条件及原判断何时应被修正；对关键产业结论尽可能用不同原始来源和不同证据类型交叉验证。若当前未找到真实反证，应注明“尚无已核实反证”并明确可证伪条件，**不能编造负面事实凑数**。同源转载不等于多源交叉。
5. **产业的专属第一锚**：资源品先检验现货/期货报价口径、供需、库存、产品价差和利润传导，再独立检查A股结构；化工类注意产品上涨与原料成本后的实际价差不同；装备/制造业注意新增订单、交付、产能和利润实现。所有行业都要检查A股公司主营与利润受益，而不是只看股票同涨。
6. **宏观风险、ETF与交易资格分离**：在产业和市场分析之外，核实整体成交、流动性、市场风险偏好对A股扩散及新仓时机的影响；宏观弱势不能自动把产业T等级下调。ETF只能作为研究完成后的参与工具、流动性和时机选择，不能反向证明产业逻辑。

**产业×市场交叉使用方式**：有产业证据但市场未确认的T0/T1/T2方向保留产业机会和市场观察价值；T1＋候选趋势主要观察；T1＋趋势确认且不过热、风险边界可靠时可研究新仓；T2＋候选/趋势确认可以进一步研究ETF；高潮/衰退、市场失效方向不进入当期新仓优先。**这些是参考框架，不能取代现行资格、排序和风险门槛，也不自动生成交易信号**。本轮研究范围不以2–3条为上限（但只将确认/候选写入正式账本）；从其中符合原资格的方向形成当期通常2–3条新仓优先榜，合格不足就少于此数或为空。市场观察池和产业机会池只是研究与报告视角，不新增下游字段。

**统一状态判断与迁移原则**：**所有历史产业阶段和A股市场状态都只是上一轮结论，不构成本轮默认判断或额外迁移门槛**。每轮研究依据截至本轮有效收盘的产业、市场正反证据重新评估本轮独立发现方向及仍需连续复核的候选/确认方向；证据充分时及时升级或降级，不要求逐级迁移、连续上涨固定天数。已退出方向只有独立重新发现时才建立新的趋势周期，绝不继承旧结论。证据不足则HOLD并记录已有信号、尚缺条件及下轮核实重点，不能机械照搬旧结论，也不能将没有新事实误写成全部旧证据已于当天重验。产业预期依独立供需、订单、价格、盈利等有效来源判断；此前核实且未被证伪的事实可沿用，不要求当天重复出现。A股市场状态变化须有本轮新增、可溯源的结构证据及独立市场佐证，综合广度、相对强度、成交、核心股与中位股扩散、分歧承接和关键反证；产业利好不能替代市场趋势确认。3/5日行情、70%广度、1.15倍量能等可作为参考统计，**不得充当固定等待期或一票否决的确认硬门槛**。程序校验证据日期、来源、独立维度和历史连续性，不自动证明结论，也不自行生成状态变更；确认趋势不自动形成新仓资格或个股READY。

## 1. 执行模式与三步主流程

### 1.1 06:30｜上一有效收盘版增量复核

仅读取上一有效交易日正式趋势账本中处于候选趋势或趋势确认、且产业生命周期未失效的方向，对真实隔夜增量证据进行复核；无新事实则保留原状态与证据日期，不在早间改写正式收盘registry/handoff。不再读取已经退出的方向或以前的观察名单。**读取上一收盘Registry/Handoff时执行下述历史输入只读校验，通过后再复核。**校验失败时报告REGISTRY_BASELINE_UNAVAILABLE。

### 1.2 18:30｜正式收盘研究

确认交易日期、收盘行情完成度和行业覆盖；仅在全市场扫描确实完整时将`scan_audit.full_market_scan_completed`记录为true。质量不足时阻断且**不能把本轮未发现解释成旧趋势失效**。

1. **独立发现**：研究模型先覆盖全行业及主要概念板块客观数据，再结合当期量价、行业/产业证据独立发现；**不能因旧池或热门板块限制扫描范围**。在独立首轮冻结前只可阅读本协议及当期客观证据；在没有读取上一轮registry/handoff/历史名单或旧候选转述前，冻结当日独立发现的方向、当前证据和反证。未知事实不得编造。独立发现可以为空，不能因为旧方向的名字而补齐。
2. **辅助交叉验证与连续复核**：独立发现冻结后，读取当日且时间口径有效的 `data/research/theme_evidence_snapshot.json#crosscheck_shortlist`（程序合并三级行业和已核验产业映射后排序，**0—3个方向**）。不排除模型已发现的方向，也不为补漏预留名额：重合则核对证据，未覆盖则补充研究，冲突则解释分歧；同源行情不能冒充独立证据。程序名单仅供复核，不能自动决定T阶段、市场状态、正式入榜或新仓资格。名单缺失/无效须标记辅助数据缺口，不得伪造复核结论，也不阻断模型独立研究。随后从GitHub读取上一轮Registry/Handoff，先运行下述「历史输入只读校验」，PASS后只复核其中处于**趋势确认/候选趋势**且生命周期未失效的方向。仅对这些方向保留历史证据和连续状态；真实证据不足时HOLD，充分时迁移。失去确认/候选资格后不再成为下一轮必读对象。此前的观察、新异动、高潮/衰退、失效无需逐项复核；在新一轮独立发现中同名出现，必须建立本轮新episode_id及新first_seen_trade_date，不读取旧历史。
3. **合并、退出校验、发布**：只将本轮确认/候选趋势写入正式账本；观察、新异动可以在本轮文字报告说明，但不写入正式账本，也不继承至下一交易日。旧有效趋势退出时，在`scan_audit.state_migration_gate.exits`记录真实原因和本轮独立市场结构反证；不生成额外历史文件。状态迁移Gate和registry/handoff成对Gate都通过后，才能安全提交两份正式文件并READBACK。

### 1.3 当期发现候选的落选审计（仅解释，不改变研究结论）

18:30独立发现冻结后、正式发布前，必须对**本轮模型已发现但未进入确认/候选正式趋势池**的方向，以及**当日程序交叉复核名单 `crosscheck_shortlist` 中未进入正式趋势池**的方向，逐一解释去向。对程序名单同时记录是否已被模型独立覆盖，以及一致、补漏或冲突的复核结论；同源行情不得当作独立置信度加成。仅在已核实属于同一产业研究对象时合并审计，并列明对应原信号。程序完整计算快照中未进入最多3个复核名额的信号只保留排序/容量事实，不冒充已研究或否决。原模型独立发现冻结顺序不变；客观扫描分数只是复核线索，不能自动决定趋势资格或回填独立发现。

对每个落选方向至少说明：①当期可溯源的正向量价及产业证据；②市场结构（广度、相对强弱、3/5日等参考窗口、量能、核心与中票扩散）和产业盈利/供需/订单传导分别有哪些真实反证或未核实环节；③**没有进入正式池的决定性原因**，明确区分「当日反弹/新异动尚未确认」「产业证据不足」「市场结构未确认」「过热/衰退」「资料不足未完成复核」等，不能以“涨幅不够”“未入选”“排名靠后”代替分析，也不能编造反证；④哪项具体可验证的新增证据将触发下轮独立重新发现或重新评估。短期窗口为负、单日放量或固定上涨天数都不得成为机械一票否决项。

在正式Registry的`scan_audit.candidate_disposition_audit`中保存本轮**落选解释快照**（建议字段：`candidate_name`、`covered_industries`、`origin`、`decision`、`supporting_evidence`、`market_assessment`、`industry_assessment`、`decisive_reason`、`missing_evidence`、`recheck_trigger`），并在中文报告中按重要性摘要展示；来源或当日数据无法取得时明确标记`UNVERIFIED`，不得伪称已完成排除研究。最多3个复核名额之外的客观信号，保留在已有计算快照及其原始排序中，必要时汇总容量缺口；不得误写为模型已研究后否决。未形成有效信号的普通行业不需逐项列举。

这只是当轮决策可审计记录，不新增需连续跟踪的观察池，不继承到下一轮模型研究，不改变正式`trends`仅含确认/候选的规则，也不新增handoff字段、不改变T等级、市场状态、优先级、配对/迁移校验或发布硬Gate。新增审计字段为兼容性附加元数据，旧版Registry缺少该字段不构成历史基线错误。若本轮无法完整解释，应如实报告审计缺口，不能把缺失解释冒充为研究结论。

## 2. 必须保留的趋势研究纪律

**三种情况要分开处理：**

- **普通波动**：单日调整、局部分歧、某只龙头走弱或资金流出，不自动升降级；若核心证据仍成立，HOLD并记录风险。不能把“旧状态未被新事实推翻”冒充“今天已重新确认所有事实”。
- **A股真实退潮**：当日或已有行情显示市场结构发生实质恶化，且上涨广度、相对强弱或核心与中位股承接等独立反证提供支持时，按统一状态迁移规则及时下调market_state，**不要求固定天数，也不另走紧急通道**。若同日主要股票普跌、关键支撑真实破位，应及时审查而非机械等次日；即使相对抗跌也需独立核实自身结构。
- **产业关键驱动证伪与新证据**：产业T等级和lifecycle_status的下降，必须有商品/政策/订单/供需/盈利等**产业自身**新反证，不能只因A股板块下跌而标产业失效。当前跟踪周期的阶段提升不能只凭单日反弹；已退出方向重新被独立发现时，必须用本轮新证据独立认证，不能继承此前的失效或确认结论。

退出新仓榜不等于产业失效；A股market_state=失效不自动等于lifecycle_status=已失效；映射不足不等于产业不存在。原有历史状态必须忠实保存，实际新状态变化须写真实原因和日期。

**商品及跨市场**：资源品主题必须分别确认对应商品第一锚、产品价差、库存/供需、A股受益公司的真实利润传导和本地行情，不把同涨当成直接受益。化工等加工行业要区分产品售价、原料成本和真实产品价差。国际报价注明时区、现货/合约性质和是否最终收盘。数据及研究资源充足时，可附5/10个相关市场交易日的条件性情景、反证和到期回验；**前瞻/回验是辅助研究，不是当日正式发布的新增硬Gate**，也不能直接决定当日状态。资金流向同样仅可作注明窗口、口径及日期的辅助证据，不能单独改变状态或排名。

## 3. 数据使用原则

模型以真实、有效的A股行情及可核验的产业信息为依据，独立研究和发现趋势。

优先使用现有全市场客观量价统计，不要求模型逐只股票重复计算。Python仅负责数据计算和必要校验，不参与趋势推荐与判断。

所有关键数据必须核对交易日期、来源及覆盖范围。数据缺失或无法核实时应如实说明，不得推测或编造。

## 4. 趋势跟踪与退出机制

**正式趋势账本`research/trend_registry.json`只保留市场状态为「趋势确认」或「候选趋势」、且产业生命周期未失效的方向。**

1. 本轮独立发现且具备真实确认/候选证据的方向进入正式账本；观察、新异动可在本轮报告说明，但不持久化，也不承担下轮复核义务。
2. 上轮仍有效的每个方向，本轮必须明确继续跟踪或有证据退出；独立扫描未命中，不等于该方向已经失效。
3. 继续跟踪时保持原`episode_id`、首次发现日期及`state_history`连续；候选与确认之间迁移仍须当前客观证据。
4. 退出时直接从本轮`trends`移除，不保留非活跃条目；必须在本轮`scan_audit.state_migration_gate.exits`填写`episode_id`、`decision=EXIT`、前后市场状态、原产业阶段、具体退出理由、当轮真实市场结构反证及独立的广度或相对强弱佐证。校验器拒绝无依据退出或漏审删除。
5. 行情覆盖不足、交易日不一致、独立扫描失败时正式发布必须BLOCK；不得据此推断旧趋势失效。
6. 同名主题后来再被独立发现时，按本轮新证据建立新周期，不继承旧判断、首次发现日期或旧证据。

**退出不建立额外历史文件。** 既有Git提交记录足以支撑事后独立回测，日常模型不读取已退出记录。

## 5. 发布与报告

**研究结论与正式数据字段**

研究完成后再形成结构化结果，不得先选字段值、再倒推产业或市场证据。正式趋势账本中：

- `trend_state`记录产业景气证据阶段；`lifecycle_status`记录产业逻辑有效性。两者依据产业自身事实判断，不能由股价涨跌直接替代。
- `market_state`独立记录A股市场趋势状态；只有「趋势确认」或「候选趋势」且产业生命周期未失效的方向进入正式账本。
- `industry_codes`、`industry_names`记录已核验的申万三级行业身份及名称；必须验证主营业务和实际受益关系，不得以概念相关性冒充真实行业归属。
- `in_new_position_priority`仅表示按现行资格和排序规则入选本轮下游买点研究优先范围，**不是买入信号，也不是个股READY结论**。候选趋势不允许在下游生成READY；个股READY须有趋势确认、独立买点结构及风险边界。WAIT、UNCERTAIN、DROP仍由下游按实际个股证据判断。

`research/trend_handoff.json`是独立的下游交接文件，不是趋势条目字段。其名单只能来自正式账本中实际获得优先资格的方向；产业阶段、市场状态、行业映射必须与账本一致，不能在交接时重新判断或改写。

**历史输入只读校验（06:30及18:30旧基线读取）**：从GitHub读取上一有效收盘Registry/Handoff原始文件，对这对旧文件运行现行严格配对校验：

~~~bash
python scripts/validate_trend_publication_pair.py \
  --registry /tmp/previous_registry.json \
  --handoff /tmp/previous_handoff.json
~~~

此检查只确认旧文件满足现行完整收盘结构，**不代表本轮新研究已发布**。所有日期一律使用严格校验，不再存在初始化基线特殊放行。失败时报告REGISTRY_BASELINE_UNAVAILABLE，不得静默继承旧趋势。18:30必须先冻结独立全市场发现，再读取这对旧文件，不得让旧名单影响独立发现。

正式收盘时，先冻结独立首轮，再按上述严格只读校验读取上一轮有效趋势账本。所有旧方向在`reviews`继续复核或`exits`有证据退出两者中必须且只能出现一次；正式账本只保存确认、候选，并依照既定业务资格生成handoff。**以下两项校验只用于本轮拟正式发布的文件，必须全部PASS，不得以旧文件的只读校验结果替代。**使用真实临时文件执行：

~~~bash
python scripts/validate_trend_state_migrations.py \
  --previous /tmp/previous_registry.json \
  --proposed /tmp/proposed_registry.json \
  --previous-blob-sha <真实上一版blob SHA>

python scripts/validate_trend_publication_pair.py \
  --registry /tmp/proposed_registry.json \
  --handoff /tmp/proposed_handoff.json
~~~

仅在全市场扫描确实完整时填写`scan_audit.full_market_scan_completed=true`。无市场结构反证退出、漏审、数据不足或任一Gate失败都禁止正式发布。两份正式文件必须交易日、资格、排名和映射一致，提交后READBACK；如实报告失败环节。

中文报告以正式账本的**趋势确认、候选趋势**为主；有当期有效证据的观察方向可以单独说明，但不得写入正式账本。新异动可概述，高潮/衰退、失效不逐项展示。报告仍包含新发现、有效旧趋势变化、重大反证、产业与市场背离、数据缺口和真实校验/提交结果。除展示过滤外不得调整市场状态或推荐资格。

19:00趋势买点榜、行情生产任务、盘中监测、持仓和趋势验证保持其既定独立流程。下游只消费已成功正式发布的当期handoff；其接口字段、行业路由、排序与资格均保持不变。
