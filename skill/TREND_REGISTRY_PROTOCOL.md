## 0. 通用产业与市场研究标准（首次发现前必读）

**产业链和A股市场链分开判断。** 研究对象是未来可能持续的产业景气及其在A股的市场体现；发现候选不等于趋势已确认，确认产业趋势也不等于立即值得买入。

1. **产业链的领先变量与未来1–2季度驱动**：判断未来1–2个季度盈利改善是否存在可核验路径；分开核实政策落地、产品价格/价差、库存与供需、订单与交付、产能利用、成本/毛利传导和经营利润。区分已发生事实、前瞻条件、未证实假设。单一政策口号、热点新闻、市场涨幅不足以证明盈利已改善。
2. **产业T阶段（证据成熟度而非股价级别）**：T0拐点观察——产业领先变量发生有来源的变化，但需求/利润传导尚不完整；T1准景气确认——多类有效证据支持未来1–2季度产业或盈利改善的驱动，关键传导与潜在反证已审查，尚未充分兑现；T2正式景气——有真实订单、供需、价格/价差、盈利或利润率等互相支持的兑现证据，产业链条相对充分。资料不足则待核验，不强凑T1/T2；正式迁移仍服从现行程序Gate。
3. **独立A股市场阶段**：只按可比的相对强度、上涨广度、成交变化、价格结构、龙头与中票扩散和分歧承接判断。新异动为早期异动；观察为有跟踪价值但尚未确认；候选趋势为量价与扩散出现初步共振但持续性待验；趋势确认为市场结构、广度、相对强度与分歧承接获得相互支持的可靠确认；根据截至本轮有效收盘已掌握的真实证据判断，不设固定上涨天数、累计窗口或单日广度比例作为确认硬门槛；高潮/衰退为过热或扩散明显衰减；失效为按真实结构反证确认市场趋势结束。**状态不是必须逐级经过的机械序列**，要依客观证据判断。
4. **正向证据、反向证据和失效条件**：每个进入正式有效趋势池的主题都要有具体正向证据，主动核查至少一项潜在推翻路径，写明指标、条件及原判断何时应被修正；对关键产业结论尽可能用不同原始来源和不同证据类型交叉验证。若当前未找到真实反证，应注明“尚无已核实反证”并明确可证伪条件，**不能编造负面事实凑数**。同源转载不等于多源交叉。
5. **产业的专属第一锚**：资源品先检验现货/期货报价口径、供需、库存、产品价差和利润传导，再独立检查A股结构；化工类注意产品上涨与原料成本后的实际价差不同；装备/制造业注意新增订单、交付、产能和利润实现。所有行业都要检查A股公司主营与利润受益，而不是只看股票同涨。
6. **宏观风险、ETF与交易资格分离**：在产业和市场分析之外，核实整体成交、流动性、市场风险偏好对A股扩散及新仓时机的影响；宏观弱势不能自动把产业T等级下调。ETF只能作为研究完成后的参与工具、流动性和时机选择，不能反向证明产业逻辑。

**产业×市场交叉使用方式**：有产业证据但市场未确认的T0/T1/T2方向保留产业机会和市场观察价值；T1＋候选趋势主要观察；T1＋趋势确认且不过热、风险边界可靠时可研究新仓；T2＋候选/趋势确认可以进一步研究ETF；高潮/衰退、市场失效方向不进入当期新仓优先。**这些是参考框架，不能取代现行资格、排序和风险门槛，也不自动生成交易信号**。完整趋势池不以2–3条为上限；从其中符合原资格的方向形成当期通常2–3条新仓优先榜，合格不足就少于此数或为空。市场观察池和产业机会池只是研究与报告视角，不新增下游字段。

**统一状态判断与迁移原则**：**所有历史产业阶段和A股市场状态都只是上一轮结论，不构成本轮默认判断或额外迁移门槛**。每轮研究依据截至本轮有效收盘的产业、市场正反证据重新评估本轮独立发现方向及仍需连续复核的候选/确认方向；证据充分时及时升级、降级或恢复，不要求逐级迁移、连续上涨固定天数，已归档方向只有在独立扫描重新发现时才建立全新趋势周期，不恢复旧周期或引入旧证据。证据不足则HOLD并记录已有信号、尚缺条件及下轮核实重点，不能机械照搬旧结论，也不能将没有新事实误写成全部旧证据已于当天重验。产业预期依独立供需、订单、价格、盈利等有效来源判断；此前核实且未被证伪的事实可沿用，不要求当天重复出现。A股市场状态变化须有本轮新增、可溯源的结构证据及独立市场佐证，综合广度、相对强度、成交、核心股与中位股扩散、分歧承接和关键反证；产业利好不能替代市场趋势确认。3/5日行情、70%广度、1.15倍量能等可作为参考统计，**不得充当固定等待期或一票否决的确认硬门槛**。程序校验证据日期、来源、独立维度和历史连续性，不自动证明结论，也不自行生成状态变更；确认趋势不自动形成新仓资格或个股READY。

## 1. 执行模式与三步主流程

### 1.1 06:30｜上一有效收盘版增量复核

仅读取上一有效交易日已发布的schema_version=2活跃registry中 market_state=候选趋势/趋势确认 且生命周期未失效的方向，对真实隔夜增量证据进行复核；无新事实则保留原状态与证据日期，不在早间改写正式收盘registry/handoff。不要读取冷归档或已退出的观察、新异动、高潮/衰退、失效主题。缺乏可靠基线时报告REGISTRY_BASELINE_UNAVAILABLE。

### 1.2 18:30｜正式收盘研究

确认交易日期、收盘行情完成度和行业覆盖，质量不足时阻断且**不能把本轮未发现解释成旧趋势失效**。

1. **独立发现**：研究模型只阅读本协议、当期全市场客观行情、行业/产业证据；在没有读取上一轮registry/handoff/冷档案/历史名单或旧候选转述前，冻结当日独立发现的方向、当前证据和反证。未知事实不得编造。独立发现可以为空，不能因为旧方向的名字而补齐。
2. **连续复核**：独立发现冻结后才读取上轮活跃registry中处于**趋势确认/候选趋势**且生命周期未失效的方向。仅对这些方向保留历史证据和连续状态；真实证据不足时HOLD，充分时迁移。失去确认/候选资格后不再成为下一轮必读对象。此前的观察、新异动、高潮/衰退、失效无需逐项复核；在新一轮独立发现中同名出现，必须建立本轮新episode_id及新first_seen_trade_date，不读取旧历史。
3. **合并、归档、校验发布**：只合并本轮独立发现与有效连续跟踪的方向，形成schema_version=2 registry；已离开连续复核的上轮非跟踪记录以完整原文写入当轮退出冷档（同名新周期亦如此）。调用V2迁移Gate，按原规则生成schema_version=1 handoff并通过成对Gate。无归档凭据禁止静默删除。归档与registry/handoff必须一起完成安全Git原子提交及READBACK，缺一不得宣称正式发布完成。

**不纳入每日主流程**：程序趋势精选候选的二次发现、模型/Python来源交叉归因、额外首轮Git冻结提交、对全部无变化主题重复深研、完整5/10/20日策略回测。已有上游客观数据统计不需要删除或改造。

## 2. 必须保留的趋势研究纪律

| 判断层 | 正式字段 | 独立证据与结论边界 |
| --- | --- | --- |
| 产业/商品第一锚 | trend_state（T0/T1/T2/待核验）；lifecycle_status（有效/待复核/已失效） | 供需、技术/政策落地、真实订单与盈利、国际商品等产业本身证据 |
| A股市场表现 | market_state（沿用现行枚举） | 同口径量价、上涨广度、相对强弱、龙头/中票扩散、承接、此前确认的价格结构 |
| A股实际映射 | industry_codes / industry_names、研究证据 | 上下游成本、主营业务、利润传导、申万三级行业真实归属 |
| 新仓优先资格 | in_new_position_priority、handoff | 沿用原新仓资格、风险、ETF时机、排序、数量标准 |

**三种情况要分开处理：**

- **普通波动**：单日调整、局部分歧、某只龙头走弱或资金流出，不自动升降级；若核心证据仍成立，HOLD并记录风险。不能把“旧状态未被新事实推翻”冒充“今天已重新确认所有事实”。
- **A股真实退潮**：当日或已有行情显示市场结构发生实质恶化，且上涨广度、相对强弱或核心与中位股承接等独立反证提供支持时，按统一状态迁移规则及时下调market_state，**不要求固定天数，也不另走紧急通道**。若同日主要股票普跌、关键支撑真实破位，应及时审查而非机械等次日；即使相对抗跌也需独立核实自身结构。
- **产业关键驱动证伪或恢复**：产业T等级和lifecycle_status的下降，必须有商品/政策/订单/供需/盈利等**产业自身**新反证，不能只因A股板块下跌而标产业失效。升级、失效后恢复也不能只凭单日反弹，要满足原独立确认条件。

退出新仓榜不等于产业失效；A股market_state=失效不自动等于lifecycle_status=已失效；映射不足不等于产业不存在。原有历史状态必须忠实保存，实际新状态变化须写真实原因和日期。

**商品及跨市场**：资源品主题必须分别确认对应商品第一锚、产品价差、库存/供需、A股受益公司的真实利润传导和本地行情，不把同涨当成直接受益。化工等加工行业要区分产品售价、原料成本和真实产品价差。国际报价注明时区、现货/合约性质和是否最终收盘。数据及研究资源充足时，可附5/10个相关市场交易日的条件性情景、反证和到期回验；**前瞻/回验是辅助研究，不是当日正式发布的新增硬Gate**，也不能直接决定当日状态。资金流向同样仅可作注明窗口、口径及日期的辅助证据，不能单独改变状态或排名。

## 3. 数据使用原则

模型以真实、有效的A股行情及可核验的产业信息为依据，独立研究和发现趋势。

优先使用现有全市场客观量价统计，不要求模型逐只股票重复计算。Python仅负责数据计算和必要校验，不参与趋势推荐与判断。

所有关键数据必须核对交易日期、来源及覆盖范围。数据缺失或无法核实时应如实说明，不得推测或编造。

## 4. V2活跃池、退出归档与独立新周期

- `research/trend_registry.json`：schema_version=2，只含本轮独立发现的方向、及由上一轮候选/确认状态连续跟踪的方向。每项有不可变的`episode_id = trend_name#first_seen_trade_date`，不得重写现有连续周期的初始日期和历史事件；观察/新异动等非跟踪状态不自动跨日继承。
- 冷档：`research/trend_archive/2026-10-16_v1_snapshot.json` 原样冻结切换前的完整V1账本；之后按日把上一轮已不处于候选/确认的完整记录存入 `research/trend_archive/YYYY-MM-DD_exits.json`。归档仅供事后策略研究，不作为日常模型输入。
- 初次从V1切换使用 `scripts/trend_registry_v2.py --mode cutover`，原交易日和事实不变；后续使用 `--mode archive-exits` 生成本轮必须归档的完整退出记录。实际状态退潮仍必须在当轮有市场结构证据时及时判断，并留在当轮记录里；下一轮再移出。不得因为本轮未发现方向而自动把已确认/候选趋势判失效。
- 同名方向重新出现：不查找历史冷档、不继承产业/市场阶段、历史证据或首次发现日期，作为独立新周期。旧档案可能保留相同名称，不构成冲突。
- 状态迁移Gate仍强制保留候选/确认方向的证据迁移与状态历史完整性；归档写入必须先校验内容与上轮真实数据完全一致，且与当轮registry及handoff同一次Git原子提交，全部回读才算发布成功。

## 5. 发布与报告

正式收盘时，先冻结独立首轮，再读取上一版活跃registry，完成必要复核并生成本轮registry、按旧资格排序的handoff与退出档案，执行：

~~~bash
python scripts/validate_trend_state_migrations.py \
  --previous /tmp/previous_registry.json \
  --proposed /tmp/proposed_registry.json \
  --previous-blob-sha <真实上一版blob SHA> \
  --archive /tmp/proposed_exit_archive.json
python scripts/validate_trend_publication_pair.py \
  --registry /tmp/proposed_registry.json \
  --handoff /tmp/proposed_handoff.json
~~~

无退出方向时可省略archive参数；有退出方向或V1首次切换时必须提供相应文件。所有正式Gate需真实返回PASS；不得用人工口头确认替代。提交后分别核对registry/handoff/归档文件和实际SHA。2026-10-16的V1初次切换属于历史保全迁移，不伪装为新交易日完成独立研究。

中文报告只逐项展示本轮 `market_state` 为**趋势确认、候选趋势、观察**且生命周期未失效的方向；新异动、高潮/衰退、失效等不逐项展示。报告仍包含新发现、有效旧趋势变化、重大反证、产业与市场背离、数据缺口和真实校验/提交结果。除展示过滤外不得调整市场状态或推荐资格。

19:00趋势买点榜、行情生产任务、盘中监测、持仓和趋势验证保持其原有独立流程。下游只消费已成功正式发布的当期handoff；原schema_version=1、signals、行业路由、排序与资格均不改变。
